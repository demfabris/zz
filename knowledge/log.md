# Update Log

## 2026-08-14
* **Creation**: Client-core rungs 4-6: new zz-client crate holds ClientCore, a sans-IO reducer (snapshot, retained viewports with patch apply and full-frame repair, overlays, key tables) driven by any shell, gated by a simulator that boots a real daemon and asserts snapshot/viewport convergence, patch/full duality, and resync soundness across seeded traffic - its first run killed an automatic sequence-gap resync, since mailbox supersession legitimately skips sequences. The KeyInput fold and typed-character table lookup moved into zz-protocol (KeyTables::resolve_input); zz-client's ChromeKeymap resolves client-local ui/browser tables and replaces zz-tui's hardcoded detach/sidebar/zoom chords. zz-client-ffi exports the C ABI (handle, wake fd, events, acquire/release viewports) declared in include/zz-client.h, and a C smoke client compiled against that header attaches, reads live viewport rows, and types through the daemon end to end.
* **Update**: Client-core rung 3: chooser keys resolve daemon-side. ChooseTreeAction::Key/ChooseBufferAction::Key carry raw key presses; the daemon maps them through new rebindable choose-tree/choose-buffer key tables (send-keys -X bindings: cursor-up/accept/cancel/search-forward/paste/delete...), preferring the typed character over the folded key name. Both hardcoded chooser keymaps (GPUI chooser/tree.rs+buffer.rs and zz-tui input.rs) are deleted; bind-key -T choose-tree now rebinds chooser vim navigation for every client.
* **Update**: Client-core rungs 1-2: canonical_key, KeyTables/KeyEngine, and COMMAND_SPECS moved from zz-mux into zz-protocol (zz-mux re-exports, client canonical_prefix mirror deleted); protocol v52 replaces ServerHello.prefix_bindings/PrefixBindingsChanged with full KeyTableSnapshot publication on every bind/unbind/source-file, and the new-session hints read the published prefix table. An older daemon must be restarted after rebuilding.
* **Creation**: Added client-core-and-contract design plan (contract consolidation, sans-IO zz-client core, deterministic simulation, FFI export).
* **Update**: Corrected wire/snapshot/lane schemas, crate map, settings census, Agent/TUI/CEF status, and stale design statuses against live source. The `ClientHello` example now matches the shipped 16-byte frame including `origin: None`, `ServerHello` carries `prefix_bindings`, the config census reads thirty-two client-local keys and eleven mux keys, Settings is nine pages titled Interface…System…About, `just run` takes `<mac|linux>` with `--verbose`/`--features` rather than Cargo passthrough, the site's command count is the catalog's real 58, and the Agent/Editor panes are documented as off-by-default rather than unshipped.
* **Fix**: Window blur now appears only through app chrome. Every pane starts from an opaque base (`theme::app_pane_background`), so the pane picker, Agent, Editor, Browser shell and its blank/loading/error states, and the terminal all cover the native backdrop instead of letting the desktop through a pane. Terminal `background-opacity` mixes the resolved Ghostty color into that base as a tint rather than punching a hole in it: `1` shows the terminal color and lower values blend toward the app surface, so the setting can no longer cancel itself against a second chrome composite. Gapped panes carry a theme-derived half-pixel inset surface ring that follows the pane's own curve, replacing the directional shadow plane that used to sit beneath translucent content. The active pane takes a washed-foreground border accent at the configured width when gapped, and in flush layouts colors only its half of each adjacent tmux-style separator, with nested T-junctions limited to the edge the pane actually touches.
* **Update**: A live `animations` switch under Interface › Tweaks (`zz/config` key `animations`, default `true`). Off sets GPUI's reduced-motion state, so transitions, spinners, switches, dialogs, notifications, and animated UI images settle on their static frame immediately, and the custom scrollbar holds full opacity and disappears without its fade instead of animating out. iOS still folds UIKit Reduce Motion in on top of the file value; desktop GPUI publishes no operating-system motion preference, so macOS, Linux, and Windows follow the key directly. Cursor blinking and Chromium page animation are content behavior and keep their own controls.
* **Fix**: CEF's `GetScreenPoint` now accounts for window zoom. `Viewport` carries a sanitized `window_zoom` (clamped to `[0.25, 4.0]`, non-finite or non-positive falling back to `1.0`), view-relative coordinates are scaled by it before being added to the unscaled window origin, and the Wayland physical-OSR path scales that origin by `scale_factor / window_zoom` instead of `scale_factor` alone. Chromium-owned popups — select dropdowns, autofill, context menus — landed at unzoomed screen coordinates before this, drifting further from their anchor the further UI zoom moved from 100%.
* **Fix**: A window switch no longer makes the daemon resend image pixels the client already holds. `refresh_terminal_visibility` now calls `suspend_terminal` for panes that left a client's visible set, which drops the pending frame and delivered generation but preserves that pane's Kitty and pasted-image ledgers; `cancel_terminal` keeps the harder ledger-clearing behavior for a pane that is really going away. Removing a pending terminal frame also retains it out of `terminal_order`, which previously leaked one queue entry per suspended pane and left the writer walking pane IDs with nothing behind them.

## 2026-08-13
* **Fix**: `cargo xtask bundle-cef` now unlinks the Linux bundle's executable before writing the new one. The daemon outlives the app and runs out of `dist/zz`, so every `just build linux` (and the packaging recipes built on it) failed with `ETXTBSY` while a session was alive; the running daemon now keeps the inode it started from and serves the previous build until restarted.
* **Creation**: Debian/Ubuntu packaging: `just deb-package` builds `dist/zz-linux.deb` from the same `stage-linux-usr.sh` tree the AppImage, tarball, and Arch packages use, and `just deb-install` hands it to `apt`. `scripts/package-deb.sh` renders `packaging/deb/control` with `dpkg-shlibdeps` output, so dependencies are computed against the build host rather than curated and only the `dlopen`ed libraries (`libwayland-client0`, `libwayland-egl1`, `libegl1`) stay hand-written; it also relocates the Arch-shaped licenses into a policy-shaped `/usr/share/doc/zz/copyright`. The package ships `/etc/apparmor.d/zz`, because Ubuntu 24.04+ denies unprivileged user namespaces to unprofiled binaries and that namespace is the sandbox the CEF runtime keeps once the legacy setuid layer is disabled — without the profile every browser pane dies at startup, which the AppImage and dev bundles are still exposed to. CI builds the deb for validation on every run; the release workflow builds it per architecture and attaches it to the GitHub release.
* **Update**: Added the `ubuntu` chrome preset, an eleventh paired light/dark family taken from Yaru 26.04's GTK `@define-color` block (`#fafafa`/`#3d3d3d`/`#cccccc` light, `#2c2c2c`/`#f7f7f7`/`#4d4d4d` dark) with Vanilla's status trio; the dark success and danger are lifted in Oklab because Yaru declares one triplet for both modes and the crimson `#c7162b` falls under 3:1 on the dark plane.

## 2026-08-12
* **Fix**: Browser keyboard, committed-text, IME, focused-frame edit, and ordered navigation commands now cross one detached foreground FIFO before entering CEF. The controller takes each burst under its GPUI update and executes it only after the app borrow is gone, preventing CEF's synchronous macOS menu validation from re-borrowing GPUI and aborting on `RefCell already borrowed`; the same boundary is used on Linux and Windows. The standard modified edit accelerators now dispatch focused-frame commands directly: Undo, Redo, Cut, Copy, Paste, Paste-and-match-style, and Select all, with the platform-native chords and address-field precedence guarded as exact sets. Browser surface key/text input bypasses root `bind -n` and `Any` bindings; from a Browser pane, only the workspace-captured tmux prefix and armed sequence use the key tables, while synchronized pane fanout stays intact. Linux/Windows `Ctrl+W` now closes the pane on its last tab like macOS. Protocol v51 carries the explicit Browser-surface input variants, so an older daemon must be restarted after rebuilding.
* **Fix**: Replaced CI retries and the non-blocking Windows test gate with deterministic test fixtures: status commands now terminate their Unix process group on timeout, daemon copy-mode and multi-client tests use controlled PTY producers, detach/reattach verification rebuilds from an explicit resync, terminal history uses a controlled PTY command, and Windows fixtures use native paths, named pipes, and shell syntax. Windows ConPTY sessions now close the pseudo-console master after child exit on the waiter thread, allowing the reader to drain through EOF and retire the pane. Every matrix leg now runs cargo test --workspace --all-features once as a hard gate. The CEF playbook now records the checked-in macOS Assets.car flow and the published Windows bundle ZIP.

## 2026-08-07
* **Update**: Made pasting an image into a **remote** pane work, where the CLI in the pane used to read its own host's empty pasteboard. The client normalizes the clipboard image, then streams it over the Control lane as `PasteUploadBegin` plus 1 MiB `PasteUploadChunk`s (protocol v43 → v44). The daemon assembles the bytes on its own host, writes `<runtime-dir>/paste/paste-<client>-<id>.<ext>` (0700/0600, newest 8 retained), and pastes that absolute path into the pane, which every path-aware CLI already understands. Two concurrent uploads per client; refusals and IO failures come back as error toasts. Local panes are unchanged.
* **Update**: Wired OSC 52 (and iTerm2 OSC 1337 Copy) clipboard writes, which were parsed and dropped. The terminal actor registers libghostty's clipboard hook, takes the `text/plain` representation under an 8 MiB cap, and raises a pane-scoped `TerminalEvent::ClipboardSet`; the daemon fans it out to every client attached to the pane's session. `set-clipboard` now carries its tmux meaning for app-initiated writes: `off` drops, `external` publishes, `on` also creates the automatic paste buffer. Clipboard reads remain unsupported.
* **Creation**: Added a source-backed NVIDIA Linux CEF accelerated-OSR investigation covering the host capability audit, CEF shared-image allocation chain, ANGLE/Ozone distinction, fallback cost, and patched-libcef acceptance test.

## 2026-08-04
* **Update**: Plasma 6.7 Wayland blur now uses ext-background-effect-v1 instead of falling through to raw transparency. The GPUI carried patch binds the advertised manager, waits for blur capability, updates existing windows, prefers ext over the legacy KDE protocol, and traces the explicit ext blur region from the rendered WindowCornerMask so transparent CSD shadow pixels and squircle corners do not leak a rectangular effect. Live WAYLAND_DEBUG verified capability 1, get_background_effect, set_blur_region, and a 13-rectangle mask inset 12 px from a 1148x726 surface; the magnified corner is clean. Published as fork patch `1819822b47` and pinned here.
* **Update**: **`window-background-blur` grew from a sidebar material into a chrome-wide one, and learned to say no.** The paint side first: `theme::sidebar_background`/`sidebar_blur` became `chrome_background`/`chrome_blur` (`BLURRED_CHROME_ALPHA = 0.9`), and every chrome plane now paints it . the workspace sidebar, both titlebar strips, and the content column the panes sit on . so the blurred desktop reads through the pane gutters instead of stopping at the sidebar seam. The invariant that makes that work is *one fill per surface*: translucent planes stacked on translucent planes multiply back toward opaque (0.9 over 0.9 is 0.99), so the pane-margin border no longer paints (`workspace/view.rs` keeps the unpainted border purely as layout inset over the app-root fill) and the empty-workspace view dropped its redundant background; the `panes_stay_opaque_and_only_the_blurred_chrome_thins` test pins the split. Second, the honest no-op: the old behavior on GNOME, WSLg, or any compositor without a blur path was a chrome that just went see-through to the raw desktop. `window/background.rs::detect_compositor_support` now probes once at startup . macOS and Windows unconditionally true, Wayland true when the registry advertises `org_kde_kwin_blur_manager` (KWin ≤ 6.3, the global gpui binds) or the `ext-background-effect-v1` staging successor (Hyprland, KWin master, niri; one throwaway `wayland-client` roundtrip), X11 true when the root window's property list carries `_KDE_NET_WM_BLUR_BEHIND_REGION` (KWin's blur effect posts and retracts it . the `KWindowEffects::isEffectAvailable` signal, so it reads "blur is on", not "KWin is running"; picom ignores the property upstream and stays conservatively opaque) . and `chrome_blur` plus the native `Blurred` request both gate on it, logging the fallback. Note the ext-only future: once a Plasma release drops the legacy global, gpui's Wayland backend needs the ext protocol to *request* blur, not just detect it. The probe type-checks on macOS through the same dev-dependency trick the X11 module already used (`wayland-client` compiles everywhere). Third, Windows actually blurs now: fork patch `b7b07b6d5d` routes `Blurred` through the documented `DWMWA_SYSTEMBACKDROP_TYPE` acrylic (`DWMSBT_TRANSIENTWINDOW`) on builds ≥ 22621 . the undocumented `SetWindowCompositionAttribute` acrylic accent is a no-op there, which is exactly the "just transparent" field report . keeps the accent path as the pre-22621 fallback, and makes `Opaque`/`Transparent` reset the backdrop to `DWMSBT_NONE` so toggling off clears it (a latent bug the Mica variants shared). The Settings row retitled "Sidebar blur" → "Window blur". First macOS eyeball found two more one-fill violations, both previously camouflaged as opaque-on-opaque: the split divider slot re-painted the base plane (the inter-pane gap stayed opaque against glass . `pane_split_surface` now paints nothing there), and `pane_corner_notches`' wedge backstop read as an opaque tip at the window corners . `PaneChrome` gained a `backstop` flag, on by default, that zz turns off while the chrome is glass, since the naked-window sliver the notch guards against cannot show through a transparent surface. Round two caught what the notch had been camouflaging in *other* pane kinds (the terminal, which rounds its own quads, was already clean): the pane picker was never registered in `synchronize_pane_corners` and painted a square base . it now carries `window_corners` and rounds its root like every other pane view . and zz-ui's `BrowserToolbar` painted its own square fill over the browser root's already-rounded plane, poking past the top arcs; the fill is deleted, the root's is the one plane. Same sweep fixed the sidebar's ghost-button menu-open state: `ButtonVariant::Ghost`'s `selected` fill was still the opaque `raised(2).active()` slab while its hover/active had long moved to the translucent `lighten/darken + opacity(0.8)` treatment . on the glass sidebar the open 3-dot menu trigger read as an opaque patch; selected now matches active. The static patch behind the host row's 3-dot turned out to be a different layer though: `workspace_tree_row`'s trailing action cluster is a *mask* . it floats over the label's tail and replays the row's fill stack, opaque base plane first, so overflowing text disappears under the buttons . and host rows show their actions permanently (`hover_actions == false`), so the mask sat as a permanent opaque patch on the glass. A mask cannot be made translucent (hiding text is exactly what opacity is for), so the layer is gone in both reveal modes: the action strip claims flex space and the label ellipsizes before it. That costs an idle row nothing, because a hover-revealed strip collapses to `w(0) + min_w_0 + overflow_hidden` until the pointer arrives . a long name still runs the full row exactly as it did under the mask, and only re-ellipsizes while the buttons are actually up. The reveal drives *layout*, not just paint, because gpui resolves a group-hover style from the group hitbox registry rather than from the paint-time hitbox (that one is only needed for self-hover), so `Interactivity::layout`'s `compute_style_internal(None, ..)` still sees the group as hovered; the width lands one frame after the pointer, on the redraw the hover already schedules. `invisible` rides along on the collapsed state, which is what makes the buttons inert rather than merely clipped: gpui returns from `paint` before descending into a hidden subtree, so they register no hitbox until they show. The browser toolbar's inactive scrim was the same shape of bug one layer down: a square `inset_0` fade over a toolbar that owns the pane's top arc, so it painted into the corner wedges; it now carries the top radii. Highlights got the same treatment as a primitive: `Colorize::washed(level)` is the translucent counterpart of `raised(level)` . the contrast pole at the step's worth of *alpha* instead of an opaque Oklab mix toward it . which composites to nearly the same pixel on an opaque plane but tints a translucent one instead of replacing it. `workspace_row_highlight` (tree rows + strip chips' live state) and the strip chips' rest fill moved from `raised(2)`/`raised(1)` to `washed`, so a highlighted row now reads as tinted glass while the blur is on, macOS-material style, with no blur-off gate needed. Verified: full `zz` suite and clippy on macOS, `cargo xwin check` for the fork's Windows tier; the Windows acrylic and the Linux probe have not run on real hardware . the DWM backdrop composes behind gpui's premultiplied DirectComposition swapchain, which should read through painted alpha without `DwmExtendFrameIntoClientArea` (upstream Zed ships Mica through the identical pipeline with no extend-frame call), and that call is the first thing to add if hardware shows otherwise.
