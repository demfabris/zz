# Overview

zz identifies every long-lived mux object with a **stable, sigil-prefixed `u64` newtype**. The five
types are `SessionId` (`$`), `WindowId` (`@`), `PaneId` (`%`), `SplitId` (`^`), and `ClientId` (`c`);
they mirror tmux's conventions so `.tmux.conf` targets and `send-keys -t %3` work as expected. All
five are generated by a single `stable_id!` declarative macro in `crates/zz-protocol/src/id.rs`, giving
them one uniform representation, `Display`, and `FromStr`. IDs are **stable for the lifetime of the daemon**:
[the GPUI app](/crates/zz.md) keeps terminal entities alive keyed by `PaneId`, and nested splits keep
their `^split` ID and ratio across layout changes.

# Representation

The macro expands to:

```rust
#[repr(transparent)]
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub struct $name(pub u64);
```

Every ID is therefore a transparent `u64`: cheap to copy, hashable (usable as `BTreeMap`/`HashMap`
keys, e.g. `WindowSnapshot.panes: BTreeMap<PaneId, PaneSnapshot>`), totally ordered, and serialized by
`postcard` as a plain `u64`. The **sigil is presentation only**: it appears in `Display`/`FromStr` and
in tmux-style command targets, never in the binary wire encoding.

# Schema . the five ID types

| Type | Sigil | Formats as | Underlying | Resolves / names |
|------|-------|-----------|------------|------------------|
| `SessionId` | `$` | `$42` | `u64` | A mux session (top of the tree) |
| `WindowId` | `@` | `@7` | `u64` | A window within a session |
| `PaneId` | `%` | `%9` | `u64` | A terminal, browser, Agent, Editor, or pending-picker leaf |
| `SplitId` | `^` | `^11` | `u64` | A split node in a window layout tree |
| `ClientId` | `c` | `c11` | `u64` | One client connection; a session can hold several at once |

# Formatting & parsing

- **`Display`** writes `concat!(prefix, "{}")`, e.g. `WindowId(7).to_string() == "@7"`.
- **`FromStr`** strips the exact prefix then parses the remainder as `u64`. Failure modes are the
  `ParseIdError` enum:
  - `MissingPrefix(&'static str)`: the string did not start with the type's sigil (e.g. `"9".parse::<PaneId>()`).
  - `InvalidNumber(String)`: the prefix matched but the remainder is not a valid `u64`.

Because each type has its own sigil, parsing is unambiguous: `"$5"` only parses as a `SessionId`, and
a bare number never parses as any ID.

# Target resolution

`PaneId`/`WindowId`/`SessionId` are how tmux-style commands address objects. The
[wire protocol](/protocol/wire-protocol.md) carries them inside `InputMessage` (`ResizeSplit { window,
split, .. }`), inside `ServerError` (`MissingTarget`, `AmbiguousTarget`, `InvalidTarget`,
`PaneNotAttached(PaneId)`, `PaneExited(PaneId)`), and inside
[snapshots](/protocol/snapshots.md). The `ChooseTreeTarget` enum (`message.rs`) unifies the three
navigable kinds (`Session(SessionId) | Window(WindowId) | Pane(PaneId)`) and delegates `Display` to
the inner ID so the tree renders `$`/`@`/`%` labels directly. Actual string→object resolution
(exact match, ambiguity, "current" fallbacks) lives in [the mux state machine](/crates/zz-mux.md); this
crate only defines the stable identities and their textual form.

# Examples

```rust
use zz_protocol::{SessionId, WindowId, PaneId, SplitId, ClientId};

assert_eq!("$42".parse::<SessionId>().unwrap(), SessionId(42));
assert_eq!(WindowId(7).to_string(),  "@7");
assert_eq!(PaneId(9).to_string(),    "%9");
assert_eq!("^11".parse::<SplitId>().unwrap(), SplitId(11));
assert_eq!(ClientId(11).to_string(), "c11");

// A bare number has no sigil, so it never parses:
assert!("9".parse::<PaneId>().is_err());   // ParseIdError::MissingPrefix("%")
```

Command-line usage mirrors tmux, e.g. `zz send-keys -t %3 "cargo test" Enter`.
